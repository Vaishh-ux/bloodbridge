# Repair report

The untouched upload is preserved as the first git commit, tagged `original-upload`
(`git checkout original-upload` to view it). Every change after that is in normal commits.

## Root causes of the original errors

1. **The React frontend source was missing.** `index.html` loads `/src/main.jsx`, but there was no `src/`
   folder at all, so the project could not be built from the supplied files.
2. **The backend package structure had been flattened.** Every Python file imports `app.models…`,
   `app.schemas…`, `app.routers…`, `app.services…`, but all files sat in one folder, so the server could not start.
3. **Files with the same name overwrote each other.** `user.py`, `match.py`, `inventory.py` and
   `notification.py` survived only as Pydantic *schemas*; the SQLAlchemy *models* `User`, `DonorMatch`,
   `BloodInventory` and `Notification` were lost. Also missing: `app/database.py`, `app/config.py`,
   `app/auth.py` (hashing/JWT helpers), and the donor and blood-request schemas.
4. **The deployed site pointed at `http://localhost:8000/api`.** Netlify hosts static files only, and no backend
   was deployed, so every API call failed. Registration showed “Registration failed. Please try again.” and the
   Requests page showed 0. The home page figures (1250+ donors and so on) were hard-coded.
5. **Dependency incompatibility.** `passlib` 1.7.4 is unmaintained and breaks with current `bcrypt` releases.
   The backend now uses `bcrypt` directly.

## Other defects fixed

- **Fabricated stock:** inventory was auto-filled with 10 available and 2 reserved units per group when a
  hospital had none. It now shows only reported stock.
- **Destructive seed:** `seed.py` ran `drop_all()` and used real hospital brand names. It is now opt-in,
  refuses non-empty or production databases, and uses clearly labelled sample data.
- **Missing authorization:**
  - Anyone could cancel any request, and any logged-in user could accept or reject any donor's match.
  - Inventory updates and donation confirmation needed no login at all.
  - Anyone could self-register as an admin.
- **Privacy leaks:**
  - Exact patient coordinates and notes were public.
  - Donor phone numbers were exposed to anyone.
  - The WebSocket accepted any `user_id` without authentication.
- **Wrong patient attached:** requests created by hospitals or admins were attached to patient #1.
- **No validation and silent defaults:** blood group, units, dates and coordinates were not validated,
  and users were silently given blood group O+ and Delhi coordinates.
- **Loose role and status rules:**
  - Login ignored the selected role.
  - Accepting a match didn't check the donor's availability or eligibility.
  - Donation confirmation could look up a *match id* as a *request id*.

## Update 2: requested improvements

- **One-step emergency request.** Visitors who aren't logged in can open *Request Blood* (or the large *Emergency Blood Request* tile on the home page) and submit straight away. A requester account is created from the same form, so they can still track the request and see donors who accept. Donor accounts are told they can't create requests.
- **Blood components.** Stock is now kept per component (Whole Blood, Packed Red Cells, Platelets, Plasma) and blood group. Only red-cell products can be issued against a request.
  - Stock is published on *Find Blood Banks* **only after an admin verifies the facility**. The facility always sees its own stock.
  - **Existing databases upgrade automatically** at startup. Old stock is copied into the new `blood_stock` table as Whole Blood, and the old table is kept, not dropped. Running the upgrade again doesn't duplicate rows. This was tested on both SQLite and PostgreSQL.
- **Quick navigation.** *Emergency Help*, *Request Blood* and *My Dashboard* are always labelled in the header. *Donate Blood*, *Find Blood Banks* and the other pages are in a second header row. The home page has quick-action tiles.
- **Layout.** Fixed a horizontal overflow on phones on *Find Blood Banks*. 10 pages × 7 screen widths and all 4 dashboards now fit on a phone without sideways scrolling.
- **Windows start scripts.** Added `start_bloodbridge.bat` (one click) and `backend/run_backend.bat`.

## Update 3: deployment

- `render.yaml` now deploys the website and backend as **one Render web service**. The backend serves the built
  React site, so there are no CORS or API-URL settings. The database is a free, permanent **Neon** PostgreSQL
  database, used instead of Render's free one, which is deleted after 30 days.
- Click-by-click guide: `DEPLOY_STEPS.md`.
- Tested by simulating Render:
  - Made a fresh clone of the repository.
  - Ran the exact build command with `NODE_ENV=production`.
  - Ran the exact start command in production mode, with a `postgres://` URL in the form Neon and Render hand out.
  - Ran the full 17-step browser test on the single address: **17 / 17 passed**, including live WebSocket updates.
- Confirmed the PostgreSQL driver accepts Neon's `channel_binding` option (bundled libpq 17).

The end-to-end steps were:
1. A hospital registers using the browser's location, then saves stock.
2. A donor and a patient register. A duplicate email shows the real server error.
3. The patient creates a Critical A+ request and one compatible donor is matched.
4. The donor receives the alert **without refreshing** and accepts it.
5. The patient sees “Donor accepted” live, plus the donor's phone number.
6. The hospital confirms the donation. The request completes and the donor becomes unavailable for the rest interval.
7. The home page's live counts update. The public feed hides private data.
8. Role-protected routes block other roles. The mobile layout has no horizontal scroll.
9. The admin verifies the facility, which is audit-logged.
